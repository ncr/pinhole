## Compiler correctness and existing derived data

The JPEG mismatch was traced to Blaze's saturating SIMD packing code:
`pack_lanes` calculated each 128-bit half using `8 / wide_bytes` instead of
`16 / wide_bytes`. The error affected signed/unsigned narrowing operations,
not the input JPEG. That revision pinned `0.20261030.1+pinhole.1`, an exact
upstream source revision with one hashed compiler patch. See
[the historical compiler bootstrap and parity gate](https://github.com/ncr/pinhole/blob/3bfdc6f/docs/blaze.md).

The public reproduction checks direct packing operations and seven JPEG
cases, comparing bytes from Blaze and an explicitly isolated Cargo build.
It also forces a genuinely scalar path rather than relying on the decoder's
ineffective unsafe-disable setting. The build and CI subsequently switched
to Cargo.

Existing average colours are recalculated from local thumbnails by the
background sync worker. Short transactions, persistent batch checkpoints
and retries cover missing/corrupt files; completion is only recorded after
all eligible thumbnails have been repaired. The repair does not download
originals or change dates, filenames, favourites or source assets. Series
invalidates only derived likeness/find results; manual grouping state stays.

## Bounded plugin queries

The API 5 promise remains compatible. Native read-only SQLite connections
run in a dedicated two-worker pool, with cancellation and a deadline active
through prepare, lock waits and execution before the first row. Admission
is limited to two jobs per plugin and eight globally. Each query has a
2-second total budget, 100,000 rows, 32 MiB accounted result memory,
1 MiB per cell, 64 columns and 64 KiB SQL. LIKE/GLOB patterns are limited
to 1,024 bytes: their native opcode does not yield to the VM progress
handler while matching, so an unrestricted pattern could defeat a deadline.
Limits reject the whole result.
Library changes and plugin shutdown cancel old work. The API reference and
agent contract explain the stable error codes and how to batch useful work.

The implementation owns its SQLite handles and uses only the native SQLite
API on those handles; it never passes Qt driver's private connections across
potentially different SQLite builds.

## Frame timing

Frame diagnostics follow the window's current screen and refresh-rate
changes. Each interval retains its own target period, so historical samples
are evaluated correctly after a move from 60 to 144 Hz, for example. Screen
moves and expose transitions drop the discontinuity rather than calling a
paused window late. The label says `late`, with the actual target Hz and a
mixed-rate indication. Late means more than 1.5 target periods; raw timing
percentiles remain available. Sorting summaries happens outside the render
thread's recording lock.

## UI and maintainable boundaries

Settings now has Sources, Photos, Plugins, Storage and Updates sections.
Tab opens settings from the grid and then traverses controls; Shift+Tab
reverses, Escape closes, comma toggles. Modal focus is contained even when
native TextInput handles Tab. The workshop adapts to narrow windows and
large fonts, with document switching and search available from the keyboard.
Shared controls expose names, roles, checked/pressed/disabled states,
keyboard activation and visible focus using the existing Omarchy theme.

Plugin loading and overlay/action collection live in `PluginPlane.qml`.
Native plugin library access, jobs, validation and query execution have
separate implementation files, preserving the scoped host and lifecycle
contract. Frame/window wiring lives in `FrameMonitor`. The grid's hot
scene-graph path and source/service ownership were deliberately preserved.

## Documentation curation and sanity review

The initial workshop wrongly bundled internal rendering, service and source
architecture notes. It now contains exactly four author documents: quick
start, public plugin API, external photo-provider protocol and agent
instructions. One C++ registry drives both the in-app navigation and CLI;
tests reject internal HDR/service/schema documents even as direct links.
Internal maintenance notes remain in the repository with an explicit scope.

The review also corrected source/grid chronology, provider error handling
and example cache identities, lazy example initialization, stale source ids
and read-only service claims. Search labels now say that they search the
current document. New `ShellButton.checkable` requires API 7, because already
released API 6 did not provide it; `holdSdr` remains API 6. Public media advice
covers the supported toolkit without publishing the rendering journal.

An additional incremental-code failure was reproduced from its preserved
executable: after a source edit, an old `u32` query result was interpreted
as `Option<u32>`. Restarting the same worker rebuilt the same target correctly
without clearing its persistent artifacts. The wrapper now isolates workers
by checkout, fingerprints Rust inputs and restarts on changes. Repeated
unchanged builds retain their worker/cache. A per-checkout lock serializes
commands; interruption reaps the foreground process and stops the worker
before unlocking. Both persistent edits and edit-then-restore during a build
invalidate its result. Twelve dedicated regression cases and an independent
review cover these paths. The exact upstream incremental query remains
unisolated; this is a demonstrated local workaround, not a claim that all
upstream incremental compiler defects were fixed.

The clean container also exposed a packaging omission: a fresh daemon tried
to fetch std sources from an unpublished patched release. The installer now
bundles and verifies the pinned 79 MB standard-library tree, independently
of HOME, daemon state and temporary bootstrap source paths.

Current guarded rebuild measurements preserve a useful advantage for the
sample core-library edit: Blaze median **6.787 s**, Cargo **22.207 s**,
**3.27×**. Warm unchanged Cargo builds have less overhead. The old 123× number
is historical. See [the method and raw samples](../build-performance.md).
